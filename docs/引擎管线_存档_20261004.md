## 二、JsonEx 序列化机制（rpg_core.js:8920-9150）

- `stringify → _encode`：给每个对象打 `@c`（自增id）；构造器名非 Object/Array 打 `@`（**直接内嵌对象，无注册表**）；循环引用替换为 `{'@r':id}`；**作为属性值的数组**包 `{'@c':id,'@a':arr}`（数组无法携带元数据）。
- `maxDepth=100` 超深抛错。
- **注意 stringify 会原地 mutate 对象**（写元数据、临时摘循环引用）—— 过程中别并发读该对象。
- `parse → _decode`：**类恢复直接查全局 `window['@名']`** → `Object.setPrototypeOf`。MV 无模块，顶层 `function Game_Xxx(){}` 声明即可自动恢复原型。
- 我们的 UnwrittenStory.js:234-245 在 extractSaveContents 里手动 setPrototypeOf 是双保险（防插件未加载时读档等边缘），保留无害。

- `setValue` 直接 `_data[id] = value`（false 也写不删）；稀疏数组过 JSON 变 null 铺底（语义无损，LZString 压缩率高）。

## 七、sentenceState 跨周目方案（定稿：方案一）

**需求**：第三夜书《相册》读前两夜玩家真实选择 —— 跨存档、跨周目。

**原作先例**：
1. **TITLEDATA**（YIN:298-345）：存档成功后 `DataManager.writeToFile(world, "TITLEDATA")` 写 save/ 目录明文 —— **跨存档跨周目的官方通道**。
2. **Permanent_Manager / CUTSCENE.json**（GTP:3245-3328）：`%LOCALAPPDATA%\OMORI\CUTSCENE.json`，玩家删档也不丢。
3. localStorage：原作仅 console 字体设置用 —— **不推荐**（清缓存即丢）。

**方案一（推荐，仿 TITLEDATA）**：
1. alias `DataManager.saveGameWithoutRescue`（GTP#176 在我们#186 之前，我们的 alias 包外层时机安全）：存档成功后 `writeToFile(JSON.stringify(前两夜 sentenceState 子集), "UNWRITTEN.json")`（复用 YIN 的 writeToFile:216）。
2. alias `DataManager.setupNewGame`（GTP:1494 已 alias，套外层）：新周目 `readFromFile("UNWRITTEN.json")` → 只合并前两夜键进全新 `$gameUnwrittenStory._pages`（本周目键不覆盖），清 `_bookState`。
3. `loadGameWithoutRescue` alias 同样合并（兜底"存档丢了文件还在"）。
4. 可选：合并入口做成 `_TDS_.UnwrittenStory.mergeLegacy(nightPrefix)` 插件命令显式触发。

**方案二（备选，借 global.rpgsave）**：挂 `makeSavefileInfo`/`saveGlobalInfo` 的 info.unwrittenLegacy —— 跟存档生命周期一致但**全槽共享单例**，双槽玩不同选择会互踩。不如方案一。

**通用注意**：跨周目文件只放 plain object（已满足）；默认态条目（variant:-1 且无标记）别写入瘦身；别动 Scene_OmoriFile.saveGame 里 TITLEDATA 写入逻辑；alias 挂 saveGame 时先调原函数。
