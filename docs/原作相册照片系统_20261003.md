# OMORI 原作 相册/照片系统解剖（2026-10-03）

> 数据源：js/plugins/Omori Photo Album.js（2674 行专用场景插件）+ data/Items.json + CommonEvents（CE601-603/207/439）+ Map050/031/466/092/098 + data/Atlas.yaml + languages/sc/ALBUM.yaml。
> 用途：**第三夜书《相册》（读取玩家前两夜真实选择）的原型依据与实现路线**。第五节是直接施工图。

## 一、系统全貌：翻相册是专用场景，不是 ShowPicture

- 入口：物品菜单用"相册"道具 → 效果码 44 → 公共事件 → `this.callAlbumMenu(itemId, mode)` → `SceneManager.push(Scene_OmoriPhotoAlbum)`。
- 三本册子：物品 966（DW）/967（BS）/968（FA），同名不同 ID，各绑 CE601/603/602。
- **"相册定义物品"**（876/889/914）用 note 承载全部配置：
  ```
  <AlbumMaxPages: 8> <AlbumMaxPictures: 48> <AlbumGroup: Faraway>
  <AlbumBookImage: faraway_town_album> <AlbumBookCoverImage: polaroid_FA_cover>
  <AlbumBackground: polaroidBG_FA> <AlbumParallax: polaroidBG_FA_day>
  <AlbumPage1Pictures: 915, 916, ...> ...
  ```
- **"照片定义物品"**（877-962，每张照片=1 个物品）：
  ```
  <AlbumGroup: Faraway> <AlbumGraphicsName: FA_A_01>      ← 大图 361×437
  <AlbumThumbnailName: FA_POLAROID_01>                     ← 缩略图 86×101
  <AlbumBackGraphicsName: AlbumPictureBack> <AlbumText: ALBUM.faraway_message1> <HideInMenu>
  ```
- 图片按虚拟路径 `img/pictures/<组>_<名>.png` 加载，由 **data/Atlas.yaml** 映射到 img/atlases/ 的图集。
- 浏览交互：←/→ 翻页（SE_turn_page）、OK 看大图（下滑入+正反面翻转）、**Shift 读手记**（文案为"..."则判定无手记）、Esc 退出。
- 放置玩法（mode 0）：底部待放栏（进场景时洗牌一次）→ 选照片 → 放槽位 → `placePictureInAlbum` 校验 `picture.id === pictures[pageIndex]`（槽位设计归属），错则弹"这张照片不该放在这里。"

## 二、进度绑定：不是开关，是"槽位表"

- 存档态：`$gameParty._albumPictures[组][槽位] = 物品ID`；API：`addPictureToAlbum/removePictureToAlbum/getAlbumPictureAtIndex/albumHasPicture/albumSize`。
- 事件指令：`this.setPictureInAlbum('Faraway', 0, 915)` / `clearPictureInAlbum`。
- **"缺页"的表达**：refreshPage 对空槽什么都不画，露出页面底图上**预印的空相纸框** —— 缺页=数据空洞，零额外美术。
- 写入点集中在各剧情地图（Map019/031/035/050/092/098/393/400/466 + CE439）。

## 三、黑照片（涂掉玛里的脸）

- **两套物品表达同一张照片**：正常 915-958，涂黑 970-994（25 张 = 有玛里出场的槽位）；素材后缀 `FA_A_XX → FA_AS_XX`、缩略图 `XXS`。
- **换装时机**：Map466（黑空间邻人卧室）Omori's Bed 的最后睡眠序列，注释原文 `NOTE IF MIXED ROUTE IS ON, CHANGE PHOTOS IN FA ALBUM HERE`：混合线（开关 1005）时 25 个槽位整组替换为涂黑版。
- 黑空间相册 24 张的文案**全部是"……"**（无手记），集齐 24 张才允许浏览模式（CE603 的 JS 聚合判定）。

## 四、Stolen Album 剧情线（开关 1000）

1. Day1 黄昏贝瑟尔家给相册（ITEM+968，可翻）→ 剧情后 **ITEM-968（从背包删除 = "被偷"的表达层）**。
2. Day1 查案：开关 1000 作为 NPC 分支散布五张图，对话拼出"奥布里拿走了"。
3. Sunday 垃圾桶找回：Map031 "PHOTO ALBUM" 事件（门控 1005）→ Kel 挖掘演出 → ITEM+968。**照片缺失不在找回时处理**——`_albumPictures` 从未清空，缺的是尚未写入的槽位。
4. 结局前 **Basil 补的第 13 张 DW 照片**（物品 963，无字家家福）：超出页表定义，由剧情 `addPictureToAlbum('Dreamworld', 11, 963)` 手工落位 —— 写入点 Map092 INITIALIZE p8 与 **CE439 `★ EPILOGUE BASIL`**（真结局收尾）。

## 五、第三夜书《相册》施工图（直接可执行）

### 数据结构照抄
```
一条照片 = 物品(note: 组/大图/缩略图/背面图/文案键)
         + 相册note槽位表（设计归属+排序）
         + 存档态 _albumPictures[组][槽位]=物品ID
         + 文案 ALBUM.xxx_messageN（"..."=无手记）
```
**解锁=写槽位；状态变化=同槽位换一套物品 ID（Normal/Variant 两套图）；补页=超表手工落位（963 模式）。**

### 读取"玩家前两夜真实选择"的三种挂法
1. **剧情开关分支**（原作主流）：第三夜开局一串 `IF 开关` 决定写入哪套照片 —— 与 Map466 "IF MIXED ROUTE" 同构。
2. **JS 聚合查询**（CE603 模式）：`[id...].filter(id => $gameParty.albumHasPicture('组', id)).length === N`。
3. **零侵入新组**（推荐给书玩法）：新建 `NightChoice` 组，每夜结局 `addPictureToAlbum('NightChoice', 槽位, 照片物品ID)`，第三夜书开局读该组渲染 —— 完全复用原作场景 UI 与存档链。

### 现成 API 清单（js/plugins/Omori Photo Album.js）
- `this.callAlbumMenu(itemId, mode)`（0=整理放置 / 1=只读浏览）
- `setPictureInAlbum / clearPictureInAlbum / albumHasPicture / getAlbumPictureAtIndex / albumSize`
- 判定文案键：`ALBUM.wrongPlacingMessage`（"这张照片不该放在这里。"）

### 资源规格（与原作一致即可混用现成图集）
- 页面底图 454×320（预印相框+手写区）、大图 361×437、缩略图 86×101、封面 241×325、背面 AlbumPictureBack。

- UI 文案：languages/sc/System.yaml 的 `albumMenu:` 节。
