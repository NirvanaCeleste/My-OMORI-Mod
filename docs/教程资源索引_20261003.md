## 三、发布打包（译稿 1.6-1.7）★ 发布前必读

### BundleTool 流程
启动游戏 → 「使用 Bundletool」→ 选模组文件夹（= F 盘工程）→ 填模组详情（**模组 ID 与 mods.one 上传 ID 一致**）→ 逐文件选处理方式 → 导出 zip 放玩家 `www/mods`。

### 每个文件四种处理方式
| 方式 | 含义 | 适用 |
|---|---|---|
| **Ignore** | 不进包 | 测试专用插件（QuickLoadOnStart / Console / Better Save and Load / 资源库 Utility 下的 DevTools） |
| **Delta** | 只含变更（.jsond/.yamld/.olid 补丁），不替换原文件 | Data 小改（如 skills.json 微调）；兼容性最好 |
| **Include** | 整文件替换 | 音频/图片/视频基本必须（增量易损坏）；大型数据改动更稳妥 |
| **Unique Name** | 插件副本重载 | 有 bug，避免使用 |

红绿灯决策：Data 小改=Delta、大改=Include；Image 小修可 Delta 但 Include 更安全；Maps 与 Tiled 同版本；Audio/Movies 一律 Include。

### mod.json（清单核心）
schema：`https://rph.space/oneloader.manifestv1.schema.json`（VSCode 自动补全校验）。
关键字段：`manifestVersion: 1`；`id`（全站唯一，冲突裁决用）；`name/description/version`；`files`（每项=文件/目录字符串数组）。JS 不必保持原目录名，mod.json 正确加载即可。

## 四、文件类型与加密映射（译稿 1.9-1.10）

| 明文 | 加密后 |
|---|---|
| .js | .OMORI |
| .json | .KEL |
| .png | .rpgmvp |
| .yaml | .HERO |
| .ogg | .rpgmvo |

（.webm/.ttf 不加密）

- `.yamld`（yaml 增量补丁）内容是 **json-patch 格式的 JSON 语法**，不是 YAML —— 易踩坑。
- `donottouch.xlxs`（翻译文件名索引）与 `rpg_[...].js` 永远不进包、不要动。
- `plugins.js` 由 OneLoader 自动处理，**不要手动编辑**（我们的 ai_play.js / ai_test.html 是测试环境注入，不属于发布包）。

## 五、英文版第 11 章：常见报错表（ds精翻里有完整版）

| 报错 | 原因与解法 |
|---|---|
| `$atlasData is not defined` | YAML 无效（最常见） |
| `tilewidth of undefined` | Tiled 旋转/镜像瓦片 → tiledfixer 或禁用旋转快捷键 |
| `hp of null` | 战斗无 Omori/Sunny 崩溃 → 装 Nomori 插件（**对我们 Basil 主角模组高度相关！**） |
| `XX_Blue.yaml` 缺失 | 盗版常见 |
| EasyTitleScreen 未配置 | 缺 OMORI_RS.png |
| 开局玩家隐身 | 起始图需 Autorun 关透明 |
| 战斗无回合顺序 | 引擎硬编码 → Geo_AutoTurnOrder |
| 图片显示在角色下方 | ID=1 的图片被强制置于角色层下 |

## 六、资源仓库速查（omori-modding-resources-main）

- `ESSENTIAL plugins/`：Fix_HorrorEffect_MemoryLeak、Geo_AutoTurnOrder、tiledfixer 系列 —— 修复类必装。
- `OneLoader plugins/`：Force_Load_First/Last、DenyInjection（全整合模组禁止共存用）。
- `Data Organization/`：TR_YamlDatabase、DoubleExtendedYAML 等 —— 把硬编码数据解耦到 YAML。
- `Battle System/`：六个子类（系统/AI/物品/菜单UI/技能/状态），如 RPH_More_Than_4_Skills、Stahl_DamagePopups。
- `Event/`、`Gameplay/`、`UI/`（yamltitlescreen、easyphotoalbum 等）、`Utility/`（console.js、pixi-panel —— **发布时必须排除**）、`Mod Compatibility/`（TR_JsExtensions 等跨模组库）。
- 文档：`OMORI Save Files.md`（各剧情节点存档下载）、`Script Tricks.md`、`Mod Licensing Guide.md`（mods.one 默认 CC BY-NC-ND 4.0）、GitHub 教程。

## 七、对本项目的行动结论

1. 发布流程已明确：F 盘工程 → BundleTool → Ignore/Delta/Include 决策 → zip。**测试三件套（ai_play.js / ai_test.html / node_compat.js）和 Console 类插件标记 Ignore。**
2. `hp of null`（战斗无 Omori/Sunny）是 Basil 主角模组的直接风险 —— 原作 FixBasilBattle.js 的历史工作正是在对抗这个；发布包应评估是否内置 Nomori 类保护。
3. 我们手头的 `donottouch.xlxs` 未动过 ✓；`plugins.js` 由 OneLoader 管，当前直接编辑的 UnwrittenStory/UnwrittenSeal 注册走的是测试环境，发布时按 mod.json 声明加载。
4. en 镜像缺失（bug_scanner 的 10 条 WARN）在发布层面有影响：玩家切英文会缺文本 —— 发布前需补 en 或在 mod.json/说明中限定语言。
