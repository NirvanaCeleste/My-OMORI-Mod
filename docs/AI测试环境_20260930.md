## 垫片解决过的问题清单（排错索引）

| 症状 | 根因 | 修法（已在垫片中） |
|---|---|---|
| FPSMeter is not defined | index.html 缺 lib 引用 | ai_test.html 补 script |
| ENOENT /OMORI/CUTSCENE.json | 读 %LOCALAPPDATA% | 虚拟目录 + 预置空 JSON |
| steamworks.initAPI 报错 | Steam 集成 | 桩返回 false（游戏自动降级） |
| crypto/Buffer 报错 | 加密数据路径 | 用 `?test` 走明文，绕开 |
| **画面黑、帧数为 0** | `SceneManager.isFocus()` 查 `window.top.hasFocus()` 内嵌环境永远 false → **场景更新/输入/渲染全跳过**（教程知识库警告的"失焦即停"） | 覆写 `isFocus=()=>true` |
| rAF 永不回调 | 无焦点环境浏览器暂停 rAF | 500ms 自检降级为 setTimeout + 重启 PIXI ticker |
| goto 无效回到闪屏 | GALV 闪屏插件劫持所有 goto | `Galv.ASPLASH.splashed = true` |
| 存档读写 | nw 文件存储 | 浏览器 localStorage / 内存覆盖层（当次会话有效） |

## 边界（不能测什么）

- **手感/节奏**：帧率仅 6fps，逐字动画时序、音画同步仍需人工在引擎里验收
- **音频**：无用户手势时 WebAudio 被浏览器锁（能跑不发声，不报错）
- Steam 成就 / OneLoader mod 注入 / 存档落盘
- `render/` 缩略图等工具产物不参与运行

## 实战补充（2026-09-30 深夜 · AI 自主玩通 night0 记录）

已验证完整闭环：开书 → 逐字书写 → 选句 → 修改 → 变体确认 → **树 s0→s1 推进 + 句子状态 + bookState 进度全部生效**。趟坑实录（下次直接抄）：

| 坑 | 解法 |
|---|---|
| 标题画面创建即崩（语言数据未就绪→catchException 停摆主循环） | ai_test.html 已注入语言预载（main.js 之前）——但最稳的是**绕开游戏加载器**：同步 XHR + jsyaml 直接把书 yaml 塞进 `LanguageManager._data.sc.text['书名']` |

| IAB 后台标签 setInterval/rAF 被节流（循环死/慢） | **同步直泵**：`for(N){ scene.update(); Input.update(); TouchInput.update(); }`——注意 OMORI 的 update 有真实时间门槛，别用 SceneManager.update()，直接调 scene.update |
| 合成 KeyboardEvent 的 keyCode 被吞 | 别走 DOM。**直接注入按钮名**：`Input._currentState['ok']=true` → 泵2-3帧 → 置 false → 泵2帧（注意 _currentState 按钮名键控，'ok' 不是键码 13/90！） |
| **OMORI 的"确定"= Z 键（keyCode 90），Enter 无映射** | 注入时无所谓键码，但人工在浏览器里按要用 Z |
| 提示窗会吃掉第一个确认键 | `DataManager.createGameObjects()` 后立刻 `$gameSwitches.setValue(2005,true)`；若提示窗已出现可 `scene.closeHint()` |

# AIPLAY 自动游玩控制器 v1.0（2026-09-30 第三批）

**一句话：`await AIPLAY.testAllBooks()` = 四本书一键回归，当前全 PASS。**

- `ai_play.js`（工程根，ai_test.html 已挂载）：AI 游玩接口——
  `openBook / testBook / testAllBooks / gotoMap / walk / interact / tap / taps / frames /
   loadYaml / assemble / status / switches / errors`
- `tools/ai_play.py`：宿主管理器（no-cache 服务器 + 速查表打印，`--open` 自动开浏览器）
- **关键设计：全同步**。IAB 后台标签的 setInterval/setTimeout 被节流至 ~1Hz，
  因此一律同步泵帧；开场/书写动画用 finishIntro/finishWriting 强制收尾。

## 首战战果：自动回归抓到两个真实 bug（均已修复）

| # | Bug | 现象 | 修法 |
|---|---|---|---|
| 1 | **同局二次开书必崩**：createPageBackground 的图片回调在位图已缓存时同步触发，此刻 `_leftArrow/_footer` 尚未创建 → TypeError | 第二次 openBook 抛 "Cannot set properties of undefined (setting 'y')" | 回调内箭头/页脚判空防御 |
| 2 | **blocks 书永远进不了选句**：`pageEditIds` 只读页级 edits，不收集 blocks 块内 edits → updateStoryState 找不到解锁页 | blocks_demo 四连击无反应，lastOp=null | pageEditIds 遍历 blocks 收集；tryShowHint 同步兼容 |

两个 bug 在三夜书（不用 blocks/单次开书）上永不显形——**这正是自动回归存在的意义**。

## 公开演示批次追加（同日晚些）

- **frames() 补丁**：`Scene_Map.updateMain` 有真实时间门槛（`currentTime >= _currentTime+16ms`），
  同步泵帧过不了 → 每帧把 `scene._currentTime` 归零穿越（书场景无此门槛所以此前未暴露）
- **缓存战争三连**：旧服务器无 no-cache 头 → 浏览器内存缓存咬死旧 ai_play.js；
  最终解 = ai_play.py no-store + ai_test.html 引用带 `?v=2` + 入口 URL 带 `&v=3`。
  **以后每次改 ai_play.js 必须同步 bump ai_test.html 里的版本号**
- **evaluate 返回 Promise 的坑**：桥不自动展开——`JSON.stringify(PendingPromise)== "{}"`,
  evaluate 里必须写 `async () => { var r = await AIPLAY.xxx(); return r; }`
- **地图步行的正确路线（未完成，已定位）**：手动装配 Scene_Map 不可行
  （create 半途崩、窗口层全空、YEP_Debugger 踩 isOpen）；
  正确做法 = 喂齐语言数据 → 走真实标题流程（commandNewGame）让框架自建 Scene_Map，
  再用穿越时间门槛的泵帧 + walk 驱动。下个里程碑。

## v1.2 完整新游戏流程（2026-10-01 凌晨 · AI 走通 531→516）

**`AIPLAY.newGame()` 一键到达 Map516 (Mod_Begin) @ (12,7)**

### 实测打通的完整链路
```
页面加载(20s) → AIPLAY.newGame()
  ├─ feedLanguages('sc')           219 yaml 同步喂入
  ├─ patchDataForTest()            equipSlots + aura 补丁
  ├─ DataManager.setupNewGame()    创建游戏对象
  ├─ forceMapLoad(531)             同步预载 RPG 数据 + Tiled 数据
  ├─ Game_Map.setup(531)           setup + locate(4,6)
  ├─ INITIALIZE autorun            解释器跑→transfer 命令
  ├─ forceMapLoad(516)             同步预载目标地图
  └─ Game_Map.setup(516)           setup + locate(12,7) → ✅ 到达
```

### 新发现（已固化进 ai_play.js v1.2）

| # | 问题 | 根因 | 解法 |
|---|---|---|---|
| 1 | `setupNewGame` 崩：equipSlots undefined | OMORI 的 Classes.json **全部无 equipSlots**（不用标准装备系统）| `patchDataForTest()` 给所有 class 补 `[1,2,3,4]` |
| 2 | `setupNewGame` 崩：aura.all undefined | OMORI 的 States 无 aura 数据 | 补丁给所有 state 补空 aura 对象 |
| 3 | 同步泵帧不推进 boot → splash | `Scene_Map.updateMain` 有 `currentTime >= _currentTime+16ms` 真实时间门槛 | 每帧归零 `_currentTime`（frames() 已内置） |
| 4 | 闪屏不放行（busy=true） | GALV 闪屏动画的 `_fadeDuration > 0` | `cs._fadeDuration=0; cs.endSplashes()` |
| 5 | 地图数据异步加载卡死 | 同步自旋阻塞事件循环 → XHR 回调永不触发 | `forceMapLoad(mapId)` 同步 XHR 预载 |
| 6 | 解释器卡在 index 0 | `SceneManager.isSceneChanging()` 误报阻断解释器 while 循环 | 多泵帧/手动 `executeCommand()` |
| 7 | `_transferring=true` 永不落 | 引擎等的 map XHR 在背景标签页不跑 | 手动 `_transferring=false` + 直接 setup 目标地图 |
| 8 | **关键引擎发现**：`SceneManager.updateScene()` 只在 `isReady()` 后调 `start()`，start 前不调 `scene.update()` | 手动调 `scene.update()` 会跳过 start 链 | **永远用 `SceneManager.updateScene()` 驱动** |

### 使用方式

```js
// 一键新游戏（含全部补丁/预载/转移）
var r = AIPLAY.newGame();  // → {ok:true, mapId:516, mapName:'Mod_Begin', x:12, y:7}

// 之后可以走/交互/开书
AIPLAY.walk('down', 3);
AIPLAY.interact();   // 按Z
```
