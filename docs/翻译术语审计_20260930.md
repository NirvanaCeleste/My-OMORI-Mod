## 一句话结论

**Flicky 点名担心的事件/地图/开关/角色四大术语全部一致，质量过硬；真正需要改的只有 1 个硬伤（Item 五五开）和 2 个小瑕疵。**

### ℹ️ 风格备注（不必改，但值得知道）

- **双语注记顺序**：全文以 `中文 (English)` 为主（94 行），列表场景用 `English (中文)`（约 6 处枚举 UI 名）——属合理排版，不算不一致；
- **Parallax 译作「视差背景」**（10+ 处，内部一致）——与 RPGMV 官方「远景」不同，但更易懂，**建议保留**；
- p187 "注标签(notetag)" 疑为 PDF 换行把"备注标签"拆断，是排版现象不是翻译错误。

# 附录二：基准术语的证据来源核实（2026-09-30 追加）

> 起因：作者质询"你确定这些术语是约定好的吗？"——原报告的基准译名表来自 AI 训练知识，
> 本节按证据强度分级如实标注。**结论：核心判定全部经受住了核实，无一需要翻案。**

## A 级（本机实证，最硬）

| 基准 | 证据 |
|---|---|
| **Item→物品** | OMORI 官方简中（游戏内 `languages/sc/System.yaml`）菜单即"物品"与"关键物品"——**统一为物品的建议由此从"训练知识"升级为"双源实证"**（叠加 B 级第 2 条） |
| State→状态、Actor→角色 | 同上（游戏内菜单"状态"、文本"角色移动"） |
| 译文的 GitHub 术语高度统一 | 全文扫描：仓库 35 处零漂移（存储库/代码库 0 处）、提交/分支/合并/克隆 全部单一译法——Flicky 关心的"GitHub 术语"块实测无问题 |
| 编辑器运行环境 | 本机 RPG Maker MV `Locale=zh_CN`（官方简体中文版），exe 二进制内检出"武器/防具/事件" |

## B 级（公开资料佐证）

| 基准 | 证据 |
|---|---|
| 角色/职业/技能/物品/武器/防具/敌人/敌群/状态/动画/图块/公共事件 | Steam 官方简中版存在（可切换语言）；[rm.rgss.cn 汉化补丁](http://rm.rgss.cn)明言"文本来源为原始版本自带**繁中**语言文件"——官方繁中数据库标签（角色/職業/技能/物品/武器/防具/敵人/敵群/狀態/動畫/圖塊/公共事件）繁转简即得本表基准 |
| GitHub：仓库/提交/分支/合并/克隆 | 与 GitHub 官方中文文档（docs.github.com/zh）通行译法一致，且译文自身已统一 |

## C 级（训练知识，未逐字核实——但审计结论不依赖它们）

| 基准 | 说明 |
|---|---|
| Playtest→测试、Parallax→远景 | 编辑器按钮级文案未在本机核实到；**但报告本就建议译文保留"视差背景"（内部一致更优）**，此基准仅用于发现"测试/试玩"混用，判定不受影响 |
| Notetag→备注标签 | "Notetag"是社区术语（官方编辑器只有"备注"字段），译文统一用"备注标签"且内部一致，无需依赖基准 |

## 诚实声明的三条边界

1. RPGMV 编辑器数据库标签的**逐字官方文本**未能在本机文件中直接提取（编译在 exe 内，二进制仅检出零星词条）；A/B 两级证据已交叉覆盖主要判定；
2. `fork/PR/issue` 译文未出现——教程原文（GitHub 章为早期版本）不涉及，无从审起；
3. `pull` 场景里"下载 16 次 vs 拉取 3 次"未逐条人工判定语境（多数应为"下载文件"正当用法），如需可再跑一轮上下文核验。
